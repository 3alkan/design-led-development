# Context Registry

This editable registry is the central discovery point for a project's relevant context. A reference makes material discoverable; it does not approve it or grant it authority.

## DLD foundation

| Source | Responsibility |
| --- | --- |
| [CONTRACT.md](CONTRACT.md) | Human–AI collaboration boundaries; adopted unchanged |
| [DLD.md](DLD.md) | Design-led software engineering methodology; adopted unchanged |
| [supporting/](supporting/) | Optional suggestions and templates, not obligations |

## Project context

Add references to the project's authoritative designs, decisions, rules, evidence, and other relevant material **wherever those sources live**. Keep proposals distinguishable from approved decisions. Suggested starting entries:

| Source | Responsibility / status |
| --- | --- |
| *(Add a relative link or external reference)* | *(Explain ownership, purpose, and approval state)* |

Before consequential work, establish applicable approvals, constraints, delegation, and evidence. Surface material missing or conflicting context rather than inferring approval from registration.
